# Offline library

The library stores the original EPUB bytes alongside a recoverable catalogue. Desktop supplies stable staged input and the isolated reader's package metadata. The checks below run against temporary libraries in the [crate integration suite](../crates/ebook-library/tests/library.rs).

- **Managed revisions.** Importing changed bytes at a known path or with a known package identifier requires a decision. Keeping a separate book gives it new identities. Replacing a revision keeps the work, edition and file IDs, retains the old bytes, and invalidates the older reading position. Check `exact_duplicate_and_review_preserve_both_revisions`.
- **Exact duplicates.** An exact current version at its known path keeps its identity and position, even when another edition shares its package identifier. Check `shared_identifier_does_not_hide_an_exact_version`.
- **Restore and browse.** After restart or reconstruction from the portable folder, search matches an edited title or author regardless of case. Original bytes, package values, catalogue IDs and the saved chapter and offset survive. Check `portable_only_rebuild_restores_bytes_metadata_and_position`.
- **Durability.** A local commit survives interruption before journal installation or before sidecar publication. An exact duplicate at a new source path records the association before reporting pending publication. After restart, changed bytes at that path still require review. Retrying publication finishes the original change once. Check `publication_interrupted_before_and_after_journal_install_retries_once` and `retry_reports_the_committed_book_while_publication_is_pending`.
- **Edited sidecars.** Replaying a revision preserves an externally edited snapshot as a proposal and restores its generated copy. Check `edited_sidecars_survive_revision_reuse_and_portable_restore`.
- **File integrity.** A symbolic link at a staged or managed file path is refused. Resolving changed managed bytes reports an error. Re-importing the verified original repairs the file. Check `refuses_symlinks_and_rejects_tampered_managed_bytes`.

- **Paged browsing.** A browse query returns its count and first 128 rows. Pages, ranks and spine groups belong to that view. Sorting accepts up to three fields, compares embedded numbers by value and puts absent values last. Every search word must occur in the title, an author or a series. A replaced view's token is refused. A view stays readable after a catalogue write: it shows current rows at the ranks they had when it opened, without books added since, and reports that it has changed. That holds for one catalogue file. When the file is replaced, as by a rebuild from the portable folder, a reader of the old file fails every call with `CatalogueReplaced` and a new reader is needed. Cancelling a query preserves the preceding view. [Browse tests](../crates/ebook-library/tests/browse.rs)
- **Survey and progress.** Survey results belong to one file version. Portable snapshots carry cover facts, word count, filing overrides, dates and reading fraction. Older records retain their original sidecar names. A replacement clears visible progress. Check `portable_only_rebuild_restores_bytes_metadata_and_position`, `survey_applies_only_to_the_version_examined` and `a_record_from_before_keeps_its_sidecar`.
- **Open and refresh.** Normal open checks the last published file and the next filename, then finishes any interrupted publication. Refresh still checks the entire chain. A change at the tip triggers replay. An incompatible SQLite catalogue is preserved beside the rebuilt file. Check `reopen_reads_one_journal_file_unless_the_tip_moved` and `reopen_alone_publishes_an_interrupted_import`.
- **Library scale.** CI checks open, search, windows, shelf data, re-sorting and indexed import lookups on 100,000 and 1,000,000 generated books. [Measured limits](../docs/design/library-browsing.md#the-benchmark)

See the [library contract](../crates/ebook-library/README.md) for the desktop API and recovery format.
