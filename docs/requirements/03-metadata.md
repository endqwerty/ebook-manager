# Metadata

The fields a book carries, how the user edits them, and how the app fetches them from
outside sources without losing the user's own work.

## Fields

The model must hold everything a file can say, so that importing a book and writing
it back loses nothing. Cardinalities below come from EPUB 3.3, FictionBook 2.1 and
ComicInfo 2.1.

| Field | How many | Structure |
|---|---|---|
| Title | One main, any number of others | Each has a kind (main, subtitle, short, collection, edition, original), a sort form, an order, and versions in other scripts with a language tag |
| Contributor | Many, ordered | A person or organisation, one or more roles (MARC relator codes: author, translator, illustrator, narrator, editor and so on), creator or contributor, sort form, name in other scripts |
| Series or set | Many | Name, identifier, kind (series or set), position as text plus a sort key. Series nest |
| Identifier | Many | Scheme plus value. One may be the file's own unique identifier, which is not proof of identity: two different books can share one |
| Language | Many, ordered | BCP 47 tags. Language of the text and original language are separate |
| Subject | Many | Scheme, code and label (LCSH, BISAC, Thema, FAST) or a plain keyword. Separate from the user's tags |
| Publisher, imprint | Many, one marked as main | Records, so a name change touches one place |
| Dates | Several | Published, first published, file modified, added to library. A date may be a year only |
| Description | One per language | Rich text |
| Rights | Many | Free text or a licence name |
| Cover | One chosen, several candidates | Source, dimensions, hash |
| Page count, word count, duration | One each | Per edition |
| Age rating | One | A listed value, with "unknown" distinct from "all ages" |
| Accessibility | Many | Access modes, sufficient access mode sets, features, hazards, summary, conformance claim, certifier, certification date |
| Layout | One set | Reflowable or fixed, orientation, spread, page direction, writing mode |
| Print page source | One | Which print edition the page numbers in the file match |
| Link to an outside record | Many | An ONIX, MARC or JSON-LD record referenced by the file |

The user's own data is kept apart from this: rating, review, tags, custom fields and
reading status. A source never overwrites them.

Identifier schemes to support: ISBN-10 and 13, ASIN (Kindle and Audible values
differ), DOI, arXiv, ISSN, OCLC, LCCN, Open Library edition and work, Wikidata, Google
volume, Hardcover, Goodreads, LibraryThing, ISFDB, Comic Vine, Metron, GCD, AniList,
MyAnimeList, GTIN, Project Gutenberg number, Internet Archive identifier, Standard
Ebooks address, BnF ARK, DNB, UUID, URL. Outside tools add their own: a Readwise book
identifier and the document hash KOReader computes.
People carry VIAF, ISNI, ORCID, LC name authority and Wikidata identifiers.

## Editing

The [local library](../../specs/library-mvp.md) supports the title and authors
portion of META-1 and retains their imported values.

- `META-1` (core) Edit every field of one book in a form, with the cover.
- `META-2` (core) Edit a selection in bulk: set, add to, remove from, find and
  replace, copy one field to another. The app previews the result and can undo it.
- `META-3` (core) Replace the cover from a file, from a page of the book or from a
  source. The app never upscales or re-encodes a cover without being asked.
- `META-4` (core) Editing a field locks it. A later fetch does not change a locked
  field. The user can lock and unlock by hand. Komga does this and users rely on it.
- `META-5` (expected) Each field shows where its value came from: the file, a
  sidecar, the user, a named source, or a conversion.
- `META-6` (expected) Write the library's metadata into the book file on request,
  for one book or many, keeping what the file had if the user asks. Writing changes
  the file's hash, so the app records the old hash as an alias. Position sync with
  hash-matching clients then keeps working.
- `META-7` (expected) Edit authors, series, publishers and tags as records: rename
  once, merge two, split one, set a sort form.
- `META-8` (expected) Sort forms are generated by rule and can be overridden. The
  rules cover family-name-first cultures, name particles, leading articles by
  language and titles that start with a number.
- `META-9` (expected) Validate identifiers: ISBN check digits, conversion between
  ISBN-10 and 13 (979 numbers have no 10-digit form), DOI and ISSN syntax.
- `META-10` (later) Rules that run on new books: "if the publisher is X, add tag
  Y", "map this source tag to that field", a list of tags to accept and a list to
  drop.

## Fetching from sources

The owner asked for trusted sources. In practice trust means the user can see where a
value came from, review it before it is applied, and rely on the app never to undo
their edits.

- `META-20` (core) Look a book up by identifier, or by title and author when it has
  none. The app shows the candidates with a confidence for each.
- `META-21` (core) A fetch is a proposal. The user sees a field-by-field comparison
  and accepts or rejects each field. Unattended fetching is an option that fills
  empty fields only, and never touches a locked one.
- `META-22` (core) Fetching works on one book, a selection or the whole library, in
  the background, within each source's rate limit, and can be paused.
- `META-23` (core) Everything works offline. A failed lookup never breaks an import.
  Lookups queue and run later.
- `META-24` (expected) The user ranks sources, overall and per field. When several
  sources answer, the highest-ranked non-empty value is proposed.
- `META-25` (expected) The user picks a cover among candidates shown with their
  size and source.
- `META-26` (expected) A match can be right for the work and wrong for the edition.
  The app does not treat a translation, an omnibus or an audiobook as the same record
  as the book it derives from.
- `META-27` (expected) Authors match to authority records, so variants and pen
  names resolve to one person.
- `META-28` (expected) Series names and positions differ between sources. The app
  keeps each source's own text beside the normalised value.
- `META-29` (expected) A book can be marked "no match exists" so the app stops
  proposing one.
- `META-30` (expected) Refetch later and see what changed at the source.
- `META-31` (expected) Ratings and reviews from a source are optional, labelled with
  the source, and kept apart from the user's own.
- `META-32` (later) An offline lookup index built from Open Library's monthly dump,
  about 12.6 GB compressed, downloaded on request. ISBN lookups then send nothing
  to any service.

## Rules the sources impose

- `META-40` (core) The app throttles per source by that source's stated rule, and
  the counters survive a restart. It identifies itself with a User-Agent that names
  the app and a project contact, and never the user.
- `META-41` (core) The app ships no shared API key. Google's API terms forbid
  credentials embedded in open-source projects, so each user enters their own key.
  Keys go in the operating system's keychain, not in the library.
- `META-42` (core) Each source has a storage class. Some results may be kept
  (Open Library, Wikidata, national libraries). Some may only be shown and copied by
  the user, not mirrored (Google Books). Some allow only
  short-lived copies and require deletion on request, within 24 hours for
  MyAnimeList, and forbid using their data as a store (AniList). The app honours the
  class per field, including the deadline.
- `META-43` (core) Before any lookup the user can see which sources will be
  contacted and what is sent: an identifier or a title and author, never the library
  list, file names or reading history. Each source has an off switch, and one
  setting stops all network use.
- `META-44` (core) The app shows the attribution a source requires. A source is
  switched on only when the app can meet its rules for storage, attribution and
  export.
- `META-45` (expected) The app does not bundle data it has no right to
  redistribute: the full BISAC list, the ISBN range file and the ISO 639-3 language
  tables. Codes that arrive in a book's metadata are stored as plain strings.

## What the app must store

- Titles, contributors, series links, identifiers, languages, subjects and dates as
  rows with the structure in the table above, never as joined strings.
- Per field: the source, the source's identifier for the record, when it was
  fetched, the match confidence, the storage class, and whether the user edited or
  locked it.
- The value each file carried at import.
- Candidate records waiting for review, with the query that found them and their
  status: pending, applied, rejected, stale.
- Cover candidates with source, address, dimensions and hash, and which is chosen.
- Authority identifiers and name variants for people.
- Each source's series text and position beside the normalised ones.
- Per source: on or off, rank, a pointer to the key in the keychain, rate-limit
  counters, the time of the last refusal and when to retry, and the marker that lets
  the next request ask only for what changed.
- A log of lookups: when, which source, what was sent.
- Hash aliases for files the app has rewritten.
- Rules from `META-10`.

## Not verified

The Library of Congress and Trove limits in the table come from a first-round report
and a search summary. Hardcover's terms and limits, ISBNdb's storage terms, Google's default daily quota,
the licence of Open Library's dumps and of the Library of Congress authority files,
and the terms of VIAF after OCLC changed its interfaces in January 2025. These pages
refused automated readers, so each needs a person to read it before the source ships.
