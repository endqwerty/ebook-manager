## 1. Findings

### 1.1 EPUB 3.3 package and metadata model (https://www.w3.org/TR/epub-33/) verified
- dc:identifier: required, repeatable; exactly one is the unique identifier named by the package's unique-identifier attribute. Reading systems must not assume the identifier identifies one publication (EPUB RS 5.3).
- dc:title: required, repeatable; first in document order is the main title. Multi-title support is inconsistent, so one element is recommended. title-type and display-seq exist but are poorly supported.
- dc:language: required, repeatable, BCP 47; first is primary. Informational only; real language and direction come from each resource.
- dc:creator and dc:contributor: optional, repeatable, order = display priority; refinable by role (usually scheme marc:relators, e.g. aut, ill), file-as (sort form), alternate-script (name in another script, language tag must differ).
- dc:date: optional, at most one. dc:subject: optional, repeatable, with authority (scheme) and term (code; term not allowed without a scheme; when a scheme is given a term is required). dc:publisher, dc:rights, dc:source, dc:type: optional, repeatable.
- dcterms:modified: exactly one, format YYYY-MM-DDThh:mm:ssZ (UTC with Z). Extra modified properties only via refines.
- belongs-to-collection: zero or more; should carry an identifier (dcterms:identifier refinement); refined by collection-type (zero or one; defined values "series" and "set") and group-position (zero or one; unsigned integer or dotted value such as 2.2.1).
- identifier-type: zero or one, on dc:identifier or dc:source, scheme such as onix:codelist5. display-seq: unsignedInt, zero or one, any property. alternate-script: any property. meta-auth is deprecated.
- refines: a relative URL to the target; chains must not be circular. Values trimmed and whitespace collapsed; required values must be non-empty after trimming.
- link element: href and rel required; rel="record" points to an external metadata record (ONIX, MARC, JSON-LD); media-type required for links inside the container; records must not be in the manifest. Deprecated rels: marc21xml-record, mods-record, onix-record, xmp-record, xml-signature. Other rels: alternate, voicing.
- Manifest: lists every resource except the package document; exactly one item with property nav; cover-image property recommended; item properties mathml, remote-resources, scripted, svg, switch. Fallback chains by idref for non-core media types.
- Spine: at least one itemref, at least one linear; each manifest item referenced once; linear defaults yes; linear="no" items must still be reachable by links; all hyperlinked documents must be in the spine; page-progression-direction ltr, rtl or default; itemref properties page-spread-left/right.
- Collections (package-level): role required, nested collections or links; creating new roles is deprecated.
- Nav document: exactly one toc nav; optional page-list (at most once, pagebreak terms); optional landmarks (at most once, epub:type required, no duplicate type+target); other nav types allowed with epub:type.
- Fixed layout rendition properties: rendition:layout (reflowable default | pre-paginated; per item overrides), orientation (auto default | landscape | portrait), spread (auto default | none | landscape | both; portrait deprecated), per-item page-spread-center/left/right, flow (auto | paginated | scrolled-continuous | scrolled-doc). Pre-paginated XHTML needs viewport meta width and height; SVG needs viewBox.
- Media overlay vocabulary: active-class, playback-active-class, duration, narrator.
- Not read (cut off): title-type values, role vocabulary, source-of (pagination), dc:source for page lists, OCF ZIP section from the current edition. [unverified] source-of="pagination" tells which print edition page numbers come from (corroborated indirectly by Ace rule epub-pagesource, below).

### 1.2 OCF container (https://idpf.org/epub/30/spec/epub30-ocf.html, EPUB 3.0 era; the 3.3 edition covers file-name and META-INF rules) verified
- mimetype first, uncompressed, no extra field, content application/epub+zip. Only stored or Deflate; ZIP encryption and split archives are errors; ZIP64 optional, readers must support it.
- File names UTF-8, at most 255 bytes, path at most 65,535 bytes, unique after case folding and normalization (3.3), forbidden characters listed (/ \ : * ? " < > | controls, private use).
- META-INF: container.xml required; encryption.xml mandatory when fonts are obfuscated; signatures.xml, rights.xml (no defined format), metadata.xml, manifest.xml optional. These are not publication resources.
- Font obfuscation: XOR of the first 1040 bytes with the SHA-1 of the unique identifier; algorithm id http://www.idpf.org/2008/embedding; reading systems with a viewport must support it. Consequence: changing the unique identifier of a book that has obfuscated fonts breaks its fonts.
- The spec gives no general recovery procedure for malformed ZIPs: how tolerant to be is a product choice.

### 1.3 Reading-system duties (EPUB Reading Systems 3.3, https://www.w3.org/TR/epub-rs-33/) verified
- Scripting: SHOULD support; scripts get a unique origin per publication instance; container-constrained scripts must not alter the host DOM; navigator.epubReadingSystem with hasFeature (dom-manipulation, layout-changes, touch-events, mouse-events, keyboard-events, spine-scripting) no later than DOMContentLoaded. If scripting is unsupported, process fallbacks. If local storage is allowed, users should be able to inspect and delete it.
- Network: remote resources SHOULD load only over https; file: URLs MUST be blocked; data: URLs must not open as top-level documents except through a user-initiated action; network access is optional, and if allowed users should be told and able to block it; external http/https links need user consent and open in a separate browser.
- XML: non-validating parser, never read external DTD subsets; entity expansion and XXE attacks to be considered.
- Fixed layout: MUST produce exactly one page per itemref; initial containing block from viewport meta; clip overflow; use first declared width/height; fill the viewport; no injected chrome. rendition:page-spread-* beats page-break-before.
- Reflowable: honour rendition:flow; align-x-center must be honoured if supported.
- Media overlays: systems with audio SHOULD support them; others ignore media-overlay and SMIL. XHTML playback required, SVG optional; missing clipBegin = 0; missing or out-of-range clipEnd = full duration; speed change recommended (half to double); playback resumes where the user navigates; skippable structures suppressed when skipping is on; escapable structures escapable. Systems with TTS should voice overlay text without audio and use speech information in the content; package durations are approximate.
- Nav: users must reach toc links and headings; page-list navigation should be offered when present; activating a link must move the position.
- Metadata: first dc:title is main; first creator primary but show all where possible; ignore unknown meta properties without failing.
- Versions: MUST attempt EPUB below 3.0; SHOULD attempt versions above 3.0.
- Security and privacy (section 15): treat any new content source (including a built-in store or sideloaded files) as insecure, e.g. ask before enabling scripting and network on first access; collect only declared data, seek consent, anonymise, no third-party access to persistent user data; do not resolve external identifiers; minimise information in requests for remote resources; avoid tracking identifiers; do not profile users from reading habits or accessibility preferences; scan content for malware on ingestion (advised).
- Non-normative user duties: expose bookshelf title, author, language as text; all controls reachable by assistive tech; full-text search; adjustable font, spacing, contrast; zoom (especially fixed layout); no physical interaction required to turn pages.

### 1.4 EPUB Accessibility 1.1 (https://www.w3.org/TR/epub-a11y-11/) verified
- Required discovery metadata: schema:accessMode, schema:accessibilityFeature, schema:accessibilityHazard. Recommended: accessibilitySummary, accessModeSufficient (repeatable sets).
- Conformance claim: dcterms:conformsTo with the exact text pattern "EPUB Accessibility 1.1 - WCAG 2.2 Level AA" (versions and A/AA/AAA vary; "none" allowed); a11y:certifiedBy (required for a claim), optional a11y:certifierCredential and a11y:certifierReport (links, via refines), dcterms:date for evaluation date.
- Reading systems: should present conformance and discovery metadata human-readably; page lists feed "go to page"; must not profile users' accessibility needs without permission; do not mine accessibility-related searches.

### 1.5 EPUB CFI (https://idpf.org/epub/linking/cfi/epub-cfi.html) verified
- Steps by "/", indirection "!" into a referenced document, character offsets zero-based between characters, temporal "~" seconds, spatial "@x:y" in range 0 to 100 (percent), so spatial points survive image resizing.
- Optional assertions in brackets (element ids, text before/after, whitespace collapsed, element boundaries ignored) "make it possible to recover intended location even after some modifications".
- Readers should check assertions; if the id or text does not match and no corrected CFI can be derived, the CFI is invalid; if a reader cannot check, it must ignore assertions; corrected CFIs should be used; reading systems and content systems should replace stale CFIs with corrected ones.
- CFIs ending in an odd step should add an explicit offset (:0 assumed). Comparing or sorting CFIs requires stripping bracketed content.
- Without assertions a CFI is purely positional (child counts), so inserting or removing an element before the target shifts it: the spec's robustness depends on assertions, and only text assertions survive reflow of markup.

(b) Metadata the data model must hold (EPUB core; extend for others)
- Identifiers: many per book; each has value, scheme/type (identifier-type with code list), is-unique-identifier flag (needed for font de-obfuscation), source (file/online).
- Titles: repeatable and ordered; main flag; title-type (main, subtitle, short, collection, edition, expanded; list not read [unverified]); sort form; display-seq; alternate-script variants with language.
- Contributors: ordered; creator vs contributor; MARC relator role (repeatable per person); file-as; alternate-script name; external author id (link, optional).
- Languages: ordered BCP 47 list; per-resource language and direction come from content, not metadata.
- Series/collections: many per book, each with name, identifier, collection-type (series, set, other), group-position as text (allows 2.2.1) plus numeric sort value; ComicInfo adds alternate series, story arc with number, series group. FB2 sequences nest [unverified].
- Dates: dc:date (0 or 1, may be imprecise, FB2 says date range possible) separate from dcterms:modified (UTC, exactly one) and from import date and file date.
- Subjects: repeatable with authority and term; genre with match weight (FB2); tags; keywords.
- Publisher, imprint, rights (free text, repeatable), source (e.g. print edition), type, description (summary short text vs annotation rich), cover (cover-image property vs FB2 coverpage vs comic FrontCover page).
- Links to external records (rel=record, media-type, ONIX/MARC/JSON-LD), kept as references plus cached copy.
- Accessibility: accessMode (multi), accessModeSufficient (multiple sets), accessibilityFeature (multi), accessibilityHazard (multi), accessibilitySummary, conformsTo text, certifiedBy, certifierCredential, certifierReport, evaluation date.
- Rendition: layout, orientation, spread, flow, page-progression-direction, per-item overrides; media overlay duration per item and narrator.
- Page navigation: whether page list exists and its page source (dc:source / pageBreakSource) so print-page numbers are tied to an edition.
- Comics: page list with type, double-page flag, width, height, size, bookmark; manga/right-to-left; age rating; community rating; GTIN.
- Audiobook: reading order with duration, narrators (readBy), abridged flag, chapters.
- Container facts per file: format and version, size, hash of whole file, hash of each content document, DRM/encryption flag, obfuscated fonts flag, remote resources flag, scripted flag, fixed-layout flag, MathML flag, validation result and message list.
- Provenance per field: which source set it (file, user, online, converter) and the file's original value, so a round trip can restore what the file said.
- Conversion record: source file hash, tool and options, output hash, list of known losses.

(c) Rules for a position or annotation to survive a file being replaced, converted or corrected
- Store several expressions of one location, as the Readium locator does: resource path (href), progression within resource, total progression, position number, a fragment/CFI, and text context (about 30 characters before, the highlighted text, after). Never store only a position number or only a CFI.
- Store the book identity separately from the file: unique identifier, per-file hash, content hash (hash of normalised text per spine item), so a replaced file can be matched to the old record. Same dc:identifier does not prove the same publication (RS 5.3 says do not assume).
- Re-anchor in this order: (1) same file hash, use stored location; (2) same content hash of that spine item, use stored fragment; (3) CFI with text assertions that still match; (4) text-quote search of before/highlight/after within the spine item, then the whole book; (5) progression fraction as last resort and mark the annotation "approximate". If none succeeds, keep the annotation as orphaned with its quoted text, never delete.
- Per CFI spec: check assertions, treat mismatches as invalid, replace stale CFIs with corrected ones when found, and ignore assertions only when unable to check.
- Keep spine item paths stable on edit (Apple's guide says to keep idrefs stable so annotations stay attached). When a conversion renames or merges files, write a path mapping table (old path to new path, old id to new id) with the output file.
- Position numbers (Readium positions) are not guaranteed stable; recompute and re-map when the file changes. Page-list numbers survive if the page source matches; store the page-source id next to any page-number bookmark.
- KOReader-style sync identifies a document by file hash and stores percentage plus a location string: a changed file means a new document id; keep an alias table (old hash to new hash) so progress carries over, and store percentages in one unit with a field saying which.
- Audio and image locations use media fragments (time in seconds, page index with rectangle in percent). For PDF store page index, page label and rectangle in percent of page size.
- Highlights in converted output: map by text, not by markup; MOBI/KF8 and kepub conversions rewrite markup, so only text-quote anchors reliably survive.

## 3. Requirements existing products get wrong (from the specs read)
- Treat the unique identifier as one of many identifiers, and do not trust it as book identity.
- Show all creators and all titles, not just the first; keep file-as and alternate-script rather than regenerating sort names.
- Do not overwrite dcterms:modified silently; update it on every edit of the package.
- Do not lose metadata the target cannot hold: warn per field and keep the original in a sidecar record.
- Keep one orphaned-annotation list instead of dropping highlights after a file replacement.
- Sandbox book scripts: unique origin, no network, no file: or data: top-level, ask once per book; show whether a book has remote resources, scripts or DRM before opening.
- Block XML external entities and DTD fetching, limit ZIP expansion (the OCF spec sets only name length limits, so the app needs its own total-size and ratio limits) [recommendation, not from a spec].
- PDF: treat attachments, forms and JavaScript as untrusted; disable JavaScript by default [recommendation].
- Keep sort rules explicit per library: collation locale, ignore punctuation yes/no, numeric ordering yes/no, leading articles (CLDR does not define article skipping).
- Do not re-encode or upscale covers; offer per-store cover checks (KDP minimum 1000x625, ratio 1.6, under 50 MB; Apple at least 1400 px short side, no upscaling).

## 4. Conversion and checking options to offer
- Conversion (from kepubify, Pandoc, Previewer facts): output format and EPUB version; split level for headings; TOC depth; title page on/off; cover replace; embed fonts; custom CSS; smarten punctuation; hyphenation on/off; find/replace in content; charset override for broken HTML; copy untouched side files; skip already converted; write beside or to folder; keep original; kepub flavour (.kepub.epub vs .kepub); fullscreen reading fix for Kobo; math as MathML or images; stable-id mode for annotations.
- OCR: language list (combinable), skip pages that already have text vs force vs redo, deskew, rotate, optimisation level and JPEG quality, output PDF/A or plain PDF, sidecar text, confidence threshold report; warn that reading order in multi-column scans may be wrong and no structure is created.
- Checking: validate package (EPUBCheck classes: mimetype, manifest, spine, ids, TOC duplicates, unknown URI schemes); accessibility check (Ace-style rules above); show messages with severity and file location; allow severity overrides and "fix automatically" only for safe fixes (add missing language, title); always check output before replacing the original.
- Store checks: cover size, EPUB version, file size (Apple 2 GB, images 5.6 MP), UTF-8/UTF-16 only, fonts listed in manifest.
- Preview: device profile preview, with warning that Enhanced Typesetting cannot be previewed by sideloading (Amazon says so).
