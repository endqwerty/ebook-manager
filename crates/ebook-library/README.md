# ebook-library

Call `Library::open(app_data)` with a private installation directory on a local Linux filesystem. Hold one handle per library. Other instances receive a lock error. Create a stable private staging file, have the isolated helper read it, and pass the same file to `import` with its bounded `ParsedMetadata` and the original source path. The crate treats the body as opaque bytes. The caller keeps the stage unchanged through any review decision. Imports accept regular files up to 512 MiB.

Start with `ImportChoice::Review`. A unique exact current version returns its existing book at a new or matching source path. A source already associated with another book prompts review. Selecting the matching book or choosing KeepSeparate returns the unique duplicate and preserves its position. Changed bytes at a known source path or with a known package identifier return candidates. Resubmit with `KeepSeparate` or `Replace(candidate.id)`. Replacement keeps work, edition and file identities, creates a new version, and retains the prior bytes. A duplicate updates the device's source association. The visible title and author fields are editable. The current version's parsed values remain in `Book.imported`.

Use `search("")` to list the shelf, or pass a title or author substring. Pass a shelf ID to `managed_file` to resolve an existing, digest-checked EPUB. Treat that path as read-only. Reading positions carry the version ID, a zero-based chapter index, and the reader's offset within it. Loading a replaced version returns an empty position.

SQLite commits an import, edit, or position together with its journal entry. Publication then installs immutable JSON changes in sequence and readable metadata snapshots under `portable/sidecars`. File contents and parent directories are flushed on publication. If publication fails after commit, the error reports that the change was saved locally. Restore writable storage and call `refresh`, or reopen. A failed import before commit can leave unreferenced bytes. After a process kill, private temporary files can remain.

To back up, close the library and copy the complete `portable` directory, including `books`, `changes` and `sidecars`. Place it under a new application directory and open there to rebuild SQLite. Preserve a damaged database in its original directory for diagnosis. The portable folder belongs to one private library and includes its reader's progress. Absolute source paths stay in local SQLite. Conflicting journal contents require restoring a consistent backup. This version supports single-device recovery. It assumes the application controls its directory while open.

Run `cargo test --manifest-path crates/ebook-library/Cargo.toml` from the repository root. The tests create their own temporary files, interrupt publication at two boundaries and reopen from portable data.

## Recovery format

Journal files have 20-digit sequence numbers beginning at one and a `.json` suffix. Each UTF-8 JSON object has `format` (currently 1), a unique `id`, its predecessor's `parent` ID (null for the first entry), and a `change`. The externally tagged `Book` change contains the catalogue snapshot, including work ID (`id`), edition, file and version IDs, title, authors, helper-supplied `imported` metadata, and `sha256`. The corresponding original is `books/<sha256>.epub`. A `Position` change carries the work ID and its version-specific reading position. The latest entry of each kind for a book gives its current state. Sequence gaps, conflicting histories, unrecognized change kinds and unexpected JSON filenames stop replay. Files without a `.json` suffix, including `.directory`, are ignored.

Each sidecar filename combines the book ID and SHA-256 of its generated pretty-printed JSON. Its contents are the same book fields as the corresponding journal change. Older snapshots remain available. To identify the current one, match its fields to the newest journal entry for that book containing a `Book` change. When publication encounters a hand-edited snapshot, it saves the original edit beside the regenerated file with a `.proposal-<uuid>` extension. If a restored sidecar has unreadable permissions or an unexpected file type, keep a separate copy of the sidecars folder and rebuild in a fresh app directory with only `portable/books` and `portable/changes`. Replay regenerates the sidecars. Inspect proposals manually and use `edit` to accept a title or author. Re-importing the original over a damaged regular managed file preserves the damaged copy with a `.damaged-<uuid>` extension before repair.

The public error marker `PublicationPending` carries the committed book ID. Call `err.downcast_ref::<PublicationPending>()` after an import, edit or progress save to distinguish a local save awaiting publication. Storage calls are synchronous. Desktop should coalesce scrolling updates and save the latest position off the UI thread when navigation settles or reading ends. Each changed position adds one durable journal file. Repeating the identical position retries pending publication. After a locally saved metadata edit, use `refresh` to retry publication without recording another edit.
